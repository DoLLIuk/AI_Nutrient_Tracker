## Что нужно лично владельцу

1. Скопировать APK на Android-телефон и открыть его. Если Android запросит,
   разрешить установку из этого источника (файлового менеджера/браузера).
2. Установить поверх существующего приложения, если подпись совместима.
   **Если Android отказывает в обновлении, не удалять приложение:** дневник
   хранится локально. Передать точный текст ошибки; возможны другая подпись
   debug/Play-сборки или более высокий установленный versionCode.
3. Разрешить камеру/выбор фотографий при запросе и выполнить таблицу ниже.
4. При ошибке записать модель телефона, Android, шаг, время и часовой пояс,
   текст/diagnostic ID; по возможности снять короткое видео.

Дополнительных действий в GCP, ввода API-ключей, создания Firestore или ключа
подписи для этого APK не требуется. Телефон пока не подключён к этому компьютеру,
поэтому установка и проверки на реальном устройстве не выполнены автоматически.
Публикация в Play Store/TestFlight в этот релиз не входит.

## Основные проверки (примерно 15–20 минут)

| № | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Трижды открыть приложение с полностью закрытого состояния, без незавершённого скана | Дневник доступен без нового ожидания восстановления; прокрутка и ручное добавление работают |
| 2 | Сфотографировать бургер с картошкой на одной тарелке | Одна запись с обоими компонентами в названии и общей порцией. Точность граммов/КБЖУ оценивается отдельно |
| 3 | Повторить с напитком/другой тарелкой на заднем плане | В запись входит основная тарелка; фон не добавляется |
| 4 | Получить результат и закрыть окно подтверждения веса | Запись уже в дневнике с оценённой порцией; перезапуск не создаёт дубль |
| 5 | Получить фото из камеры, на экране уточнений закрыть приложение и открыть снова | Черновик «Your photo is ready»; нет автоматического распознавания. Continue продолжает, Discard удаляет черновик |
| 6 | Отправить фото, сразу свернуть/закрыть приложение; открыть позже | Результат восстанавливается либо показано состояние незавершённого запроса. В итоге одна запись на исходную дату |
| 7 | Перед подтверждением веса отключить интернет, ввести другое значение (например 300 г), подтвердить и закрыть приложение; включить сеть и открыть снова | Восстанавливается введённое значение, пересчитывается итог. Фото повторно не анализируется |
| 8 | Изменить вес вручную/отметить его проверенным, сохранить и перезапустить | Значение и отметка сохраняются. Простое переименование не отмечает вес проверенным |
| 9 | Начать скан на выбранном прошлом дне, во время ожидания переключиться на сегодня | Запись остаётся на исходном дне |
| 10 | Во время запроса открыть дневник, прокрутить, перейти в профиль/добавить вручную | Нет блокирующего затемнения. Тонкий индикатор не мешает действиям |
| 11 | Удалить уже сохранённую запись и перезапустить | Запись не появляется снова |
| 12 | Отменить камеру/выбор фото; отдельно отказать в разрешении | Нет зависшего затемнения и неожиданного платного запроса; доступен ручной ввод |

Для пункта 7 при открытии до восстановления сети нажать Check scan после её
возвращения. Нет обещания работы процесса после принудительного закрытия:
восстановление выполняется при следующем открытии. Если сервер завершился в
неопределённый момент, возможен OPERATION_UNCERTAIN; тот же ключ не запускает
новый платный анализ. Новый скан после явного Discard — отдельная операция.

## Сложные проверки вместе с разработчиком

- **Android уничтожает приложение во время камеры:** с подключённым ADB открыть
  камеру из приложения; пока камера на переднем плане выполнить
  `adb shell am kill com.golov.aicalorietracker`, затем закончить съёмку.
  Ожидание: возвращённое фото восстановлено как черновик. Это отличается от
  `force-stop`, который может отменить доставку результата камеры.
- **Позднее подтверждение:** задержать ответ сети, подтвердить вес, закрыть окно,
  изменить запись или удалить её до ответа. Новая правка/удаление имеют приоритет.
  Этот порядок уже проверен автоматическими тестами с управляемой задержкой.
- **Плавность:** измерить холодный запуск и кадры в release APK на реальном
  телефоне, с черновиком и без него. Сравнить с прежней версией на том же устройстве.
  Автотесты доказывают отсутствие ожидания recovery перед экраном, но не измеряют
  производительность конкретного телефона.
- **Нет повторного списания:** проверить число provider-вызовов по журналам
  запросов/usage для одного operation ID. Один лишь одинаковый результат в UI
  этого не доказывает; отдельный новый скан той же фотографии считается новым.

## Веб-демо и gateway

Мобильный клиент → `photo-food-api`.
Веб-клиент → `ai-nutrient-demo-gateway` → тот же `photo-food-api`.

Gateway скрывает серверный ключ от браузера, проверяет origin и ограничивает
демо: 3 анализа на browser ID/UTC-день, 50 суммарно; 9/150 подтверждений.
Повторная HTTP-попытка тоже расходует квоту демо. Это не второй AI-анализатор.

Основной backend и gateway уже обновлены. Новый Flutter Web интерфейс не
публиковался: запрет push в remote сохранён. Для проверки нового восстановления
сейчас использовать APK. Для обновления GitHub Pages потребуется отдельная
публикация frontend после разрешённого push/выбранного способа публикации.

## Ограничения и отложенные функции

Точная политика обрезанных фото, контроль съеденной доли и связанные отдельные
компоненты ещё не реализованы. Бургер + картошка сейчас одна запись; уменьшение
общих граммов масштабирует всю тарелку. Будущая модель описана в
[PHOTO_FLOW_FUTURE_COMPONENTS.md](PHOTO_FLOW_FUTURE_COMPONENTS.md).

Откат GCP возвращает прежний код, но не отменяет данные Firestore. Новый клиент
при старом backend запрещает сканирование без поддержки recovery. Команды отката
сохранены в backend-проекте: `docs/RELEASE_2026-09-27.md`.
